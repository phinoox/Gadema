# Deterministic ID Generation

In GaDeMa, certain types of data—specifically those defined as Enums in the codebase—require stable and predictable identifiers. To achieve this, we use a deterministic GUID generation system that maps enum members to unique, repeatable GUIDs.

This approach allows us among other things, for code-defined tags (like `GameTag` or `WritingTag`) to have permanent, unchangeable identities that can be safely referenced in database relationships and logic across different environments.

---

## 1. The Core Mechanism: `ReservedGuid`

The foundation of this system is the `ReservedGuid` class. Unlike standard random GUID generation (which produces a new value every time), `ReservedGuid` creates a unique ID based on two integer inputs: a **Module Index** and a **Serial Number**.

### Implementation Details
The implementation uses a bitwise approach to construct a 16-byte array, embedding the module index and serial number into specific byte offsets. This ensures that as long as the input integers remain the same, the resulting GUID will be identical.

```csharp
// Internal structure of the generated bytes:
// [8][9] -> Module Index
// [10]   -> System Anchor (Fixed)
// [12][13][14][15] -> Serial Number
```

---

## 2. The `EnumGuidExtensions` Pattern

To make this usable for developers, we provide the `EnumGuidExtensions` class. This allows any Enum to be converted into a deterministic GUID through a simple extension method.

### The `[ModuleIndex]` Attribute
For an enum to participate in this system, it must be decorated with the `[ModuleIndex]` attribute. This attribute defines the "namespace" or module index for that specific enum within the global system.

```csharp
[ModuleIndex(2)] // Assigns index 2 to this module
public enum GameTag
{
    Fire = 0,
    Water = 1,
    Stunned = 2
}
```

### The `ToGuid<T>()` Method
The extension method performs the following steps:
1.  Reads the `[ModuleIndex]` from the enum type.
2.  Converts the specific enum member value into an integer (the "Serial").
3.  Calls `ReservedGuid.Create(index, serial)` to return the final GUID.

```csharp
// Example usage:
// Returns a unique, deterministic GUID based on Module Index 2 and Serial 0
Guid fireId = GameTag.Fire.ToGuid(); 
```

## 3. Summary of Workflow

| Step | Action | Responsibility |
| :--- | :--- | :--- |
| **1. Define** | Create an Enum with `[ModuleIndex]` | Developer |
| **2. Map** | Call `.ToGuid()` on an enum member | Extension Method |
| **3. Generate** | Compute bytes using index and serial | `ReservedGuid` |

## ⚖️ Trade-offs

| Pros | Cons |
| :--- | :--- |
| **Stability**: IDs for code-defined tags never change, even if the database is wiped or re-seeded. | **Complexity**: Requires manual management of module indices to avoid collisions. |
| **Predictability**: Allows developers to hardcode expected GUIDs in tests or configuration files. | **Strictness**: Throws an exception if the `[ModuleIndex]` attribute is missing, requiring developer discipline. |
